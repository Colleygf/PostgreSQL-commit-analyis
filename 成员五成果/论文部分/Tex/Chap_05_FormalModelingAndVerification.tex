\chapter{形式化建模与修复正确性验证}\label{chap:formal}

\section{验证目标与 Z3 环境配置}
本章旨在利用微软 Z3 约束求解器（Z3 Theorem Prover），对前述章节发现的 Bug 及其修复方案进行数学层面的形式化验证。形式化验证不依赖于测试用例的覆盖率，而是通过构建状态机模型和谓词逻辑，证明修复后的逻辑在所有合法输入空间内均满足安全性规约，彻底消除“静默逻辑失效”风险。

\section{核心实验一：C 源码逻辑修复的符号化验证}
基于第三章提取的补丁特征，本节选取了 PostgreSQL 底层最具代表性的逻辑冲突案例进行建模验证，证明其从“概率安全”向“确定安全”的转化。

\subsection{算术溢出防护验证（基于 2025\_e2ceff13.diff）}
\textbf{建模对象}：PostgreSQL 核心宏 \texttt{pg\_add\_size\_overflow} 及其加法边界检查。

\textbf{验证逻辑}：
在旧逻辑中，加法溢出检查由于未考虑 64 位无符号整数的回绕（Wrap-around）特性，可能被特定的输入组合绕过。我们使用 Z3 的位向量（BitVec）进行建模：
\begin{itemize}
    \item \textbf{旧逻辑谓词}：$\text{sum} = a + b, \text{is\_overflow} = (\text{sum} < a)$。
    \item \textbf{安全规约}：$\forall a, b \in \text{UInt64}, \text{is\_overflow} \iff (a + b > \text{MaxUInt64})$。
\end{itemize}

\textbf{实验结论}：Z3 成功构造了 SAT 反例，证明了旧逻辑在某些编译器优化路径下会导致溢出检查静默失效。而新逻辑在所有位向量空间内判定均为 \textbf{UNSAT}（无反例），证明了修复方案是数学完备的。

\subsection{缓冲区边界动态加固（基于 2022\_a405908f.diff）}
\textbf{建模对象}：LZ4 压缩模块中的 \texttt{maxlen} 与 \texttt{footer\_bound} 约束。

\textbf{实验分析}：
通过 \texttt{another\_z3\_solver.ipynb} 中的脚本验证，原代码过度依赖 \texttt{Assert} 断言。
\begin{itemize}
    \item \textbf{脆弱路径发现}：当 \texttt{maxlen = 1, footer\_bound = 2} 时，旧逻辑在生产环境（Non-debug）中会跳过检查直接导致越界写入。
    \item \textbf{修复验证}：新引入的 \texttt{enlargeStringInfo} 动态扩容机制在模型中表现为：无论初始 \texttt{maxlen} 为何值，系统均能通过状态转移确保剩余空间始终满足安全性判定条件。
\end{itemize}

\subsection{进程清理状态机验证}
针对 PostgreSQL 在异常退出时的清理逻辑，我们建模了 \texttt{ShutdownMode} 与 \texttt{Action} 的关系。
\begin{itemize}
    \item \textbf{验证发现}：旧逻辑仅在 \texttt{FatalError} 时终止子进程。Z3 发现了一个 SAT 状态：当处于 \texttt{Immediate} 模式但非 \texttt{FatalError} 时，子进程可能残留。
    \item \textbf{新逻辑}：引入 \texttt{Or(FatalError, ShutdownMode == Immediate)} 条件。经验证，该逻辑在所有模式下均能保证子进程的正确终止（\textbf{UNSAT}）。
\end{itemize}

\section{核心实验二：配置同步逻辑的 Python 脚本验证}
针对第四章提到的 \texttt{generate\_editorconfig.py} 静默失效问题，本节构建了三维状态模型。

\subsection{变量定义与状态抽象}
\begin{itemize}
    \item \texttt{FileType} ($T$)：$\{0, 1, 2, 3\}$（未知, C, H, Python）；
    \item \texttt{Attribute} ($A$)：$\{0, 1, 2\}$（无, 缩进过滤, 其他）；
    \item \texttt{OutputAction} ($S$)：$\{0, 1, 2\}$（无动作, 生成 C 配置, 生成 Python 配置）。
\end{itemize}

\subsection{安全规约与修复验证}
定义的正确性命题为：$\forall T, A: (T=3 \land A=1) \implies S=2$。通过 \texttt{verify\_fix.py} 补全状态机映射后，求解器在所有 36 种合法输入组合下均未发现违反规约的情况，证明修复逻辑达到了全域覆盖。

\section{本章小结}
本章利用 Z3 求解器为前文的静态模式和动态案例提供了底层逻辑支撑，说明结合形式化验证的“证据链”能够显著提升对高风险模块修复结论的可信度。
